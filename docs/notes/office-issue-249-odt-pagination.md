# Office issue #249: ODT pagination

Issue #249 lists 54 ODT and FODT samples whose page count differs from LibreOffice
24.2.7.2's. I reproduced each one at commit `8a20ca0` with the conformance harness
(`eng/run-office-conformance.sh`, pinned fonts `office-fonts-2`). To see how Writer
behaves outside the reference, I converted cut-down documents with the local
LibreOffice 24.2.7.2 (`soffice --convert-to pdf`) and read positions with
`pdftotext -bbox`. "Severity" is the harness's `severityScore`.

| Sample | Cause | Outcome |
| --- | --- | --- |
| `odfexport`/`ooxmlexport` `tdf160518_{auto,page}_in_{default_paragraph,text_body}_style.fodt` (8), `odfexport/data/tdf132599_{auto,page}.fodt` | Heading 1's parent is `Heading`, and the document does not define it. Writer creates the pool style a parent name refers to when it is needed (`SwDocStyleSheet::SetParent`, `lcl_FindParaFormat` with `bCreate`). The reference draws the 49 pt heading in Liberation Sans Bold, 12 pt above and 6 pt below. The reader cut the chain at the missing parent, so the heading was serif with no spacing. That put 10 body lines on page 1, against Writer's 9: 2 pages against 3. | **Fixed.** `OdtStyles.Chain` adds the built-in `Heading` (already used for an unstyled `text:h`) when a chain reaches an undefined parent of that name. 3 pages, all 10 pass. |
| `odfexport/data/tdf160253_ordinary_numbering.fodt` | The document states no notes configuration. Writer's `SwEndNoteInfo` defaults to the `Endnote` pool page style. The import only replaces it with a page style the configuration names. So the endnote goes on a page of its own after the body. The reader only did that when `text:master-page-name` was stated. | **Fixed.** ODT endnotes start on their own page unless the `ContinuousEndnotes` setting is on. The writer now states that setting for a document whose endnotes run on, so a round trip keeps them where they were. 2 pages. |
| `odfexport/data/tdf160253_outline_numbering.fodt` | The same endnote cause. Also, its `Standard` master page names no page layout. Writer leaves that page style at its pool defaults, A4 with 2 cm margins. The reader kept the caller's Letter page with 1 in margins. | **Fixed.** A master page that names no page layout the document defines falls back to `WriterDefaultPage`. A layout without `page-layout-properties` keeps the old behaviour: `font_used_in_header_only.fodt` lost its header band that way, so I narrowed the rule. |
| `layout/data/tdf146704_EndnoteInSection.odt`, `odfimport/data/ooo32780-1.odt` | The section style holds `text:notes-configuration text:note-class="endnote"`, so the section collects its endnotes at its end (`SwFormatEndAtTextEnd`). Its `text:start-value` (6) restarts their numbering at vi. The reader handled only the footnote class, so the endnote went to an endnote page. | **Fixed.** Endnote collections share the footnote collection's mechanism (`SectionFootnotes`). `NoteNumberer` numbers them from their own start. A one-column section sets them under the page's note separator, as LibreOffice draws the container there. `footnote-collect-at-end-of-section.fodt` shows the line for footnotes too and still passes. One page each. In `ooo32780-1.odt` the notes of the three-column section sit at the end of the flow, not at the foot of each column as Writer sets them, but the sample passes. |
| `layout/data/quo_vadis_footnote.fodt`, `layout/data/ergo_sum_footnote.fodt` | (1) A footnote taller than the room under its citation was set whole, over the body. Writer splits it: what fits stays, and the rest continues at the foot of the next page. (2) Writer keeps at least a fifth of the page for the body (`SwFootnoteBossFrame::GetVarSpace`). That is why ergo_sum keeps 7 of its 8 lines on page 1, though all 8 would fit. (3) A note paragraph that names no style is in Writer's `Footnote` style: 10 pt, with a 6 mm hanging indent for the label. The reader set it at 12 pt. The continuation notices (`text:continuation-notice-*`) are not drawn by 24.2 either. | **Fixed.** `DocumentLayout.TakeNotes` / `TakeCarriedNotes` split a note into parts (`NotePart`) under a 80% cap. The ODT reader gives unstyled note paragraphs `Footnote`/`Endnote`, and adds the built-in style where it is missing or named as a parent. 2 pages each. |
| `layout/data/Cool16072_rowWithOwnFootnoteKeepsThePage.fodt`, `layout/data/Cool16072_rowMovesPastAPushedFootnote.fodt` | A keep-together row fills page 2 and cites a long footnote. Writer sets the whole note on page 3, because the citation cannot move. broilerdoc drew the note over the row. | **Fixed.** A note with no room under a citation that cannot be cut shorter goes to the next page whole. A splittable row's note is still set under it as before. When it was carried too, `tdf134965.odt` got worse, because its row should be cut short for the note, which the row splitter does not do. 3 pages each. |
| `layout/data/Cool16071_footnoteTailKeptWhenTruncated.fodt` | Footnotes in table rows: Writer moves footnote 1 to the page after its citation and splits footnote 2 across pages 3 and 4. | **Not fixed.** Severity improved 808.4 → 804.3 (the footnote style). Moving a note off its citation's page needs the row splitter to account for notes. |
| `layout/data/table-0-height-rows.fodt` | Most rows hold only paragraphs that a `text:hidden-paragraph` with a true condition hides. Writer's hidden paragraphs take no height, so these rows have none, and the table fits on page 1. The reader gave each such cell the empty line an empty cell has. | **Fixed.** `OdtTableReader` adds that line only when the cell is empty, not when its paragraphs are hidden by their fields (`OdtReader.HidesEveryParagraph`). One page. |
| `odfimport/data/tdf76349_1columnBreak.odt`, `ooxmlexport/data/tdf133370_columnBreak.odt` | A `fo:break-before="column"` on a single-column page or section. Writer takes a column break only inside a column frame (`SwFlowFrame::IsColBreak` uses `FindColFrame`). The layout broke the page there, which is right for Word. | **Fixed.** New `DocumentStyleDefaults.ColumnBreaksNeedColumns`, set by the ODT reader. With it, the layout ignores a column break where the text has one column. DOCX and RTF are unchanged. One page each. |
| `ooxmlexport/data/tdf132149_pgBreak2.odt` | (1) A header or footer's `fo:min-height` is its whole least height, the spacing included. The reader added the spacing on top. I measured this in 24.2: a header of at least 1.5 cm with 1 cm of spacing starts the body 1.5 cm down, and one of at least 0.5 cm starts it below the line and the spacing. A footer of at least 0.998 cm with 0.499 cm of spacing behaves the same way. (2) A paragraph whose own break opens a page keeps its space above (`SwFlowFrame::HasParaSpaceAtPages`, `IsPageBreak`). The ODT reader never set `PageBreakKeepsSpaceAbove`. | **Not fixed, declined.** Both rules are measured and right. Together they passed this sample and 15 others outside the cluster (among them `tdf124678_*`, `tdf135056.odt`, `tiledrendering/data/{multiline,numrules,search}.odt`). But they made passing samples fail. `pagelinespacing/data/headerFooter.fodt` failed because its body heading is register-true (`style:register-true`), and only the grid Writer snaps it to brings it back to the reference. broilerdoc has no register-true layout, and the old, too-tall header hid that. `uiwriter/data/tdf139638.odt` failed because its headings drift by a fraction of a point each down page 3, and the space above now kept at the top of the page pushed its last heading over. `abi11870-2.odt` (817.4 → 830.2) and `fdo114306_2.odt` (737.7 → 761.4) also got worse. The patch is kept for when register-true and line rounding exist. |
| `uiwriter/data/tdf34957.odt` | Tables that keep with the next paragraph. Writer moves the last row with the paragraph and does not leave a repeated heading row alone on a page. It also fits fewer rows of the multi-page table on page 4. | **Not fixed.** Table keep-with-next pagination. It is its own piece of table-flow work. |
| `ww8export/data/tdf79186_noLayoutInCell.odt` | A frame anchored in a cell with `style:flow-with-text="false"` overflows the cell in Writer and does not grow the row. broilerdoc grows the row and moves it to page 2. | **Not fixed.** It needs a model property for objects that do not follow the text flow in cells. |
| `layout/data/tdf171161.fodt` | `style:text-scale="50%"` (character scaling) on 750 pt text. The model has no horizontal character scale, so "a" wraps to page 2. | **Not fixed.** Character scaling is a model, layout and painter feature. |
| `ooxmlexport/data/tdf172113_linespacingNumbering.odt` | The list level's `text:style-name` character style sets the labels at 32 pt, and the taller lines run to page 2. broilerdoc sizes a label from the paragraph's first run. | **Not fixed.** List label character styles are not modelled. |
| `layout/data/nested-sections.fodt` | LibreOffice 24.2 draws outer section 2 over inner section 1. The upstream test `layout3.cxx testNestedSectionOverlap` asserts that they no longer overlap. broilerdoc draws them apart, which is the fixed rendering. | **Not fixed, not recorded.** A reference defect, but I could not trace the fixing commit from this environment: GitHub and gerrit were not reachable for LibreOffice core. |
| `layout/data/tdf169399.fodt`, `layout/data/tdf169607-big-letters.fodt`, `layout/data/multiline-field-in-columnar-section.fodt` | 24.2 defects that the upstream tests describe: `layout6.cxx testTdf169399` ("without the fix there were two pages"), `testTdf169607` (three pages, one before the fix) and `layout5.cxx` (one page, a layout loop before the fix). broilerdoc already draws each one the fixed way. | **Not fixed, not recorded.** As above: no fix commit could be traced for a defect row. |

## Verification

- Harness on the 54 cluster samples, before (`8a20ca0`) and after: 0 → 21 passed.
  - Passing now: the 10 tdf160518/tdf132599 samples, both tdf160253 samples,
    `tdf146704_EndnoteInSection.odt`, `ooo32780-1.odt`, `table-0-height-rows.fodt`,
    `tdf76349_1columnBreak.odt`, `tdf133370_columnBreak.odt`, `quo_vadis_footnote.fodt`,
    `ergo_sum_footnote.fodt` and both `Cool16072_row*` samples.
  - Of the 33 still failing, none got worse. `Cool16071_footnoteTailKeptWhenTruncated.fodt`
    went 808.4 → 804.3. The rest are unchanged.
- Outside the cluster, `tdf117448.fodt`, `tdf125310.fodt`, `tdf161172.fodt` and
  `tdf52391.fodt` pass now (the default page). `tdf125310b.fodt` improved
  718.8 → 342.4, `footnote-in-2-column-section.fodt` 440.4 → 30.2 and
  `wideBoxInFootnote.fodt` 775.0 → 762.9.
- Layout sweep over all 3,847 `.odt`/`.fodt`/`.docx`/`.rtf` samples against the
  baseline: 42 samples changed. I ran the harness on them, on the cluster, and on every ODT
  sample whose notes take the new note style (an indent change the sweep does not
  fingerprint): 76 samples. Every sample that passed before still passes. No failing
  sample got worse. The robustness inputs `forcepoint76-1.rtf` and `forcepoint93-1.rtf`
  still pass.
- New tests, each failing before its change: `OdtIssue249OdtPaginationTests`
  (Broiler.Documents.Odt.Tests, 10 tests) and `DocumentLayoutIssue249OdtPaginationTests`
  (Broiler.Documents.Pagination.Tests, 7 cases). `OdtNoteTests.A_Document_That_States_No_Configuration_Numbers_As_LibreOffice_Does`
  now expects `EndnotesStartOnNewPage`, which is Writer's default. The full solution test
  run passes.
