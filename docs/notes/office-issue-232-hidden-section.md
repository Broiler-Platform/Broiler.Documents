# Office issue #232: hidden sections, symbol fonts and OLE previews

| Sample | Cause | Outcome |
| --- | --- | --- |
| `uiwriter/data/HiddenSection.odt` | Three sections say `text:display="condition"` with `text:condition="ooow:Hide==0"` and `text:is-hidden="true"`. The condition evaluator only split on spaces, so `Hide==0` was not understood and was treated as "shown". LibreOffice's PDF is blank. | Fixed. `OdtReader.EvaluateCondition` now returns null when it cannot evaluate a condition (unparsed, or a variable the document never declares), and `IsSectionHidden` then falls back to `text:is-hidden`, the result LibreOffice stored when it saved. The render is now blank like the reference. Test: `OdtNonPrintingTests.A_Condition_That_Cannot_Be_Evaluated_Keeps_The_Stored_Is_Hidden`. |
| `ooxmlexport/data/fdo79968.docx` | The body is a single `w:object` (an embedded PowerPoint slide) whose preview is an EMF that draws its words, "Cloud Computing" and "-Akshay", with `EXTTEXTOUTW`. `EmfRasterizer` draws no text by design, so the preview is blank. | Not fixed. Drawing EMF text needs fonts when the image is read, or the EMF has to become vector content in the model. Both are a feature, not a focused fix. |
| `ooxmlexport/data/fdo78384.docx` | A 72 pt `w:sym w:font="Wingdings" w:char="F0E7"`. The reference fonts have no Wingdings: LibreOffice draws a notdef box, and the graphics stack draws its fallback "?" glyph. The reader keeps U+F0E7 in Wingdings correctly. | Not fixed. Both renderers lack the font, and the fallback glyph comes from Broiler.Graphics, not this repository. |
